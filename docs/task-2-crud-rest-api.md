# Task 2: Product entity, JPA repository and CRUD REST API

## Goal
- Create a simple `Product` entity.
- Manage it with **Spring Data JPA** repositories, *without* `spring-boot-starter-data-rest`.
- Expose create, read, update and delete operations through a REST controller, and test them with curl.

## Dependencies (`build.gradle`)

```groovy
implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
implementation 'org.springframework.boot:spring-boot-starter-webmvc'
runtimeOnly    'com.h2database:h2'                                        // in-memory database
testImplementation 'org.springframework.boot:spring-boot-starter-data-jpa-test'  // @DataJpaTest
```

`spring-boot-starter-data-rest` is deliberately **not** used. The repository is not exposed over HTTP automatically;
all endpoints are written by hand in `ProductController`.

## Entity: `model/Product.java`

| Field | Type | Notes |
|---|---|---|
| `id` | `Long` | `@Id @GeneratedValue(strategy = IDENTITY)`, generated by the database |
| `name` | `String` | required |
| `description` | `String` | optional |
| `price` | `BigDecimal` | required, `precision = 10, scale = 2` (`BigDecimal` avoids rounding errors with money) |
| `quantity` | `int` | items in stock |

`Product` started as a Java `record`, but **records can't be JPA entities**: JPA needs a no-argument constructor
and mutable fields. It is now a regular class with a `protected` no-argument constructor for JPA.

## Repository: `repository/ProductRepository.java`

```java
public interface ProductRepository extends JpaRepository<Product, Long> {
    List<Product> findByNameContainingIgnoreCase(String name);
}
```

`JpaRepository` provides `save`, `findAll`, `findById`, `existsById`, `deleteById`, paging and more. Spring Data
generates the implementation at runtime. `findByNameContainingIgnoreCase` is a *derived query*: the SQL is built
from the method name.

## REST controller: `controller/ProductController.java`

Base path: `/api/products`

| Method | URL | Body | Success | Errors |
|---|---|---|---|---|
| `POST` | `/api/products` | `ProductRequest` | `201 Created`, `Location` header, saved product | |
| `GET` | `/api/products` | | `200`, list of products | |
| `GET` | `/api/products/{id}` | | `200`, product | `404` |
| `PUT` | `/api/products/{id}` | `ProductRequest` | `200`, updated product | `404` |
| `DELETE` | `/api/products/{id}` | | `204 No Content` | `404` |

`ProductRequest` (`controller/ProductRequest.java`) is a record holding `name`, `description`, `price` and `quantity`.
Clients can't send or change the `id`.

## Sample data
`SampleDataLoader` is a `CommandLineRunner` that saves three products on startup (Laptop, Mouse, Laptop Stand) and
prints them. It is a separate `@Component` rather than part of `HomeworkApplication`, so `@DataJpaTest` doesn't
run it and pollute the repository tests.

`spring.jpa.show-sql=true` in `application.properties` prints the SQL Hibernate runs.

## Testing with curl

Since task 3 the API needs a JWT, so get a token first (see [task 3](task-3-security.md)):

```bash
TOKEN=$(scripts/get-token.sh admin admin)
AUTH="Authorization: Bearer $TOKEN"

curl -i -X POST http://127.0.0.1:8080/api/products -H "$AUTH" -H 'Content-Type: application/json' \
     -d '{"name":"Keyboard","description":"Mechanical keyboard","price":79.50,"quantity":20}'
curl http://127.0.0.1:8080/api/products -H "$AUTH"
curl http://127.0.0.1:8080/api/products/4 -H "$AUTH"
curl -X PUT http://127.0.0.1:8080/api/products/4 -H "$AUTH" -H 'Content-Type: application/json' \
     -d '{"name":"Keyboard Pro","description":"RGB","price":99.00,"quantity":15}'
curl -i -X DELETE http://127.0.0.1:8080/api/products/4 -H "$AUTH"
```

Results from the test run:

| Request | Result |
|---|---|
| Create | `201`, `Location: /api/products/4` |
| Read all | `200`, 4 products |
| Read one | `200` |
| Update | `200` |
| Delete | `204` |
| Read after delete | `404` |
| Update or delete a missing id | `404` |
